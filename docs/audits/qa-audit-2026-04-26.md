## 🔴 Bugs — Things That Are Actually Broken

### 1. Stats counter animates 97.2% as "97+"
**File**: `script.js` → `animateStats()`  
The function uses `parseInt(stat.textContent)` to read the target number. `parseInt("97.2%")` returns `97`, and the counter ends by setting `stat.textContent = target + '+'`. So the SOC 2 score stat goes from 0 to 97 and lands on **"97+"** instead of **"97.2%"**. This undersells one of your strongest resume metrics. The 2000+ and 500+ stats work because they already end in "+", but the percentage is broken.

**Fix needed**: Detect the "%" suffix and handle it separately, e.g. animate as a decimal and restore the "%" at the end.

---

### 2. Duplicate `.cisco-grid` rule in mobile breakpoint cancels itself
**File**: `styles.css` — `@media (max-width: 768px)` block  
There are two `.cisco-grid` declarations in the same media query:
```css
.cisco-grid {
  grid-template-columns: 1fr;      /* sets single column */
  max-width: 300px;
}

.cisco-grid {
  grid-template-columns: repeat(2, 1fr);  /* immediately overrides to 2 columns */
}
```
The second rule wins, so the `1fr` single-column layout is never applied. The Cisco badges section stays at 2 columns on small phones when it should stack to 1. This is likely a copy-paste leftover.

---

### 3. Profile photo has a duplicate CSS declaration
**File**: `styles.css`  
`.profile-photo` is declared twice. The first sets only `pointer-events: auto`; the second (immediately after) sets all the actual styling. The first declaration is dead code and will confuse anyone editing the file.

## 🟠 High Priority — Professional / Functional Issues

### 4. Footer copyright year is 2025 — it is now 2026
**File**: `index.html`, line 857  
```html
<p>&copy; 2025 Christopher Corbin. Deployed via GitHub CI/CD → AWS S3 + CloudFront.</p>
```
Your current employer dates include "Jan 2026 – Present", so a visitor will immediately see the discrepancy. Should be `2026` or `2025–2026`.

### 5. Contact email shown on site ≠ email that receives form submissions
**File**: `index.html` contact section vs `config.js` / `contact_handler.py`  
- **Displayed on site**: `Christophercorbin@gmail.com`  
- **SES notification destination**: `christophercorbin24@gmail.com`  

These are two different email addresses. If a recruiter tries to email the address shown on the site and it is inactive, you will miss the message. Whichever is the real inbox needs to be consistent everywhere.

### 6. No favicon
**File**: `index.html` `<head>`  
There is no `<link rel="icon">` tag. Every page load makes a 404 request for `/favicon.ico`, the browser tab shows a generic icon, and some link-preview tools (Slack, LinkedIn) won't render a site thumbnail. A quick fix is a simple SVG favicon using your brand orange (`#ff9900`).

---

### 7. Project links missing `rel="noopener noreferrer"`
**File**: `index.html` — all 6 project `<a target="_blank">` links  
The project card links open in a new tab but lack the security attribute:
```html
<a href="https://github.com/..." target="_blank" class="project-link">  ← missing rel
```
Without `rel="noopener noreferrer"`, the opened tab gets a reference back to your page via `window.opener`. This is a known security vector. The contact section GitHub link correctly has the attribute — the project section links do not.

---

### 8. `resume.html` has no navigation back to the portfolio
**File**: `resume.html`  
If someone lands on `/resume.html` directly (e.g., via a direct link), there is no header, no nav, no "Back to portfolio" link. It is a dead end. A small header or a single back-link at the top would fix this.

A recruiter opening both will notice the mismatch immediately. Pick one and be consistent — likely "Cloud Infrastructure Developer & Security Engineer" since that is your current role title.

## 🟡 Medium — Accessibility & UX Issues

### 11. About and Experience sections share the same background color
**File**: `styles.css`  
Both `.about` and `.experience` use `background: var(--bg-secondary)` (the same `#f8f9fa` grey). On the live page they visually merge into one long block with no clear section boundary. Every other section alternates to white, so this pairing stands out. One of the two should use `var(--bg-primary)` (white) to maintain the alternating rhythm.

---

### 12. Hamburger menu is a `<div>`, not a `<button>`
**File**: `index.html` — `<div class="hamburger">`  
The mobile menu toggle is a `<div>` with a click handler. It is not keyboard-focusable, has no `aria-label`, and is not announced by screen readers as an interactive control. It should be a `<button aria-label="Toggle navigation" aria-expanded="false">`.

---

### 13. `<nav>` has no `aria-label`
**File**: `index.html`  
When a page has a single `<nav>` it is inferred, but best practice (and WCAG 2.1 AA) is to label it explicitly: `<nav aria-label="Main navigation">`. Screen reader users will hear "Main navigation" when they land on it.

---

### 14. No skip-to-content link
**File**: `index.html`  
Keyboard-only users must tab through the entire 6-item navigation on every page load to reach content. A hidden "Skip to main content" anchor at the top of the `<body>` (revealed on focus) is the standard fix and a basic WCAG requirement.

---

### 15. Google Fonts loaded without `preconnect`
**File**: `index.html` `<head>`  
```html
<link href="https://fonts.googleapis.com/css2?family=Inter..." rel="stylesheet" />
```
There is no `<link rel="preconnect" href="https://fonts.googleapis.com">` or `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>` before it. Adding these two lines shaves ~100–300ms off the first font byte, which directly affects Largest Contentful Paint on the hero section.

---

### 16. Contact form textarea has no character feedback
**File**: `index.html` + `script.js`  
The message field has a 1000-character max and 10-character minimum enforced at submission, but there is no live counter. Users do not know they are close to the limit until they hit "Send" and get an error. A live `<span>` showing remaining characters would prevent failed submissions.

---

### 17. `window.load` opacity fade can hide the page if JS is slow
**File**: `script.js`  
```js
window.addEventListener('load', () => {
  document.body.style.opacity = '0';
  ...
  setTimeout(() => { document.body.style.opacity = '1'; }, 100);
});
```
`opacity: 0` is applied at load time and only lifted after a setTimeout. If JS is slow or blocked, the page is invisible. The pattern also causes a very brief flash on every hard reload. A CSS `@keyframes` fade-in on `body` achieves the same effect without the JS risk.

## 🟢 Low / Polish

### 18. Typing animation fires on every hard refresh
**File**: `script.js` → `typeWriter()`  
The hero title types out on every page load. It is a nice first-impression effect but can feel slow on return visits. Consider running it only once using `sessionStorage` as a flag, or reducing the per-character delay.

---

### 19. No `<meta name="robots">` and no sitemap.xml
For a public-facing career portfolio, telling Google how to index the site matters. No `robots` meta tag means crawlers use their defaults. There is no `sitemap.xml` in the repo, which slows indexing. A minimal one-file sitemap pointing to `/` and `/resume.html` is a 5-minute fix.

---

### 20. Google Analytics ID is `null`
**File**: `config.js`  
`GOOGLE_ANALYTICS_ID: null` — analytics is wired in the code but not enabled. You have no insight into how many recruiters visit the site, what sections they spend time on, or where they drop off. Even a basic GA4 property would give you this data.

---

### 21. Project card badge says "Live Repo" for all three projects
**File**: `index.html` — all three `.project-badge` spans  
All badges read "Live Repo" — this is accurate (they link to GitHub) but generic. Badge text like "GitHub" with the GitHub icon, or differentiating between "Live Demo" (if a project has a deployed URL) and "View Code" would be more descriptive.

---

### 22. Font Awesome loaded from CDN with no subresource integrity (SRI)
**File**: `index.html`  
```html
<link href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.0.0/css/all.min.css" rel="stylesheet" />
```
No `integrity` or `crossorigin` attribute. If Cloudflare's CDN were ever compromised, a malicious stylesheet could be injected. This is low risk for an icon library but is standard practice to add SRI hashes for third-party CSS/JS.
